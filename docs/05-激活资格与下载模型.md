# 第 5 步：激活资格（用户空间重启）并下载模型

> 目标：让资格判断服务 eligibilityd 重新读取地区，两项资格从 `2` 变成 `4`，然后等模型下载完成。

## 5.1 为什么扩展已经生效，资格还是"不符合"

作者用日志和多次重启对照，确认了下面的时间顺序：

```
开机 → launchd 启动
     → 约 5 秒后 eligibilityd 启动，读取设备地区：此时还是 CH  ← 被缓存在进程里
     → RegionSpoof 生效，地区变成 LL/A
     → eligibilityd 之后虽然会重新计算资格，但沿用进程里缓存的旧地区 → 一直判"不符合"（2）
```

所以需要让 eligibilityd **在 RegionSpoof 生效之后重新启动一次**。

### 直接重启这个服务？不行

```bash
sudo launchctl kickstart -k system/com.apple.eligibilityd
```

作者实测返回 `Operation not permitted while System Integrity Protection is engaged`（退出码 150）。我们只豁免了内核扩展签名，SIP 仍在保护系统服务，这是好事，不要为此去完全关闭 SIP。

## 5.2 解法：用户空间重启

```bash
sudo launchctl reboot userspace
```

它会重启**内核以外的所有进程**（相当于注销后重新开机，但内核不重启，RegionSpoof 保持加载）：

- 所有 App 会被退出，**先保存工作**。
- 屏幕会黑一下，然后回到登录界面，重新登录即可。全程约 1 分钟。
- 新启动的 eligibilityd 会读到 LL/A。

## 5.3 验证资格

```bash
sudo plutil -extract OS_ELIGIBILITY_DOMAIN_GREYMATTER.os_eligibility_answer_t raw \
  /private/var/db/eligibilityd/eligibility.plist
sudo plutil -extract OS_ELIGIBILITY_DOMAIN_SIRI_WITH_APP_INTENTS.os_eligibility_answer_t raw \
  /private/var/db/eligibilityd/eligibility.plist
```

两项都应变成 **`4`**（符合）。作者的结果：用户空间重启后两项立即变为 4，"设备地区"这一项输入的状态也从 2 变为 3（ELIGIBLE）。

想看每一项输入的详细状态：

```bash
sudo /usr/libexec/PlistBuddy -c "Print :OS_ELIGIBILITY_DOMAIN_GREYMATTER:status" \
  /private/var/db/eligibilityd/eligibility.plist
```

> 作者机器上"当前位置国家（COUNTRY_LOCATION）"这一项输入始终显示 2，但两个最终资格依然是 4，**不需要修改定位**。最终以两个 domain 的 answer 为准，不要因为某一个输入是 2 就去改定位。

如果资格仍是 2，大多数情况卡在：
- Apple 账户地区是中国大陆（见第 1 步）
- 系统语言与 Siri 语言不一致，或不是英文
- 扩展没加载 / 地区没变（回第 4 步核对）

## 5.4 下载 Apple Intelligence 资源

资格变 4 后：

1. 打开 **系统设置 → Siri**。页面会显示 **Powered by Apple Intelligence**，并提示正在准备资源（下载模型）。
2. 保持联网、插电，等待下载完成。模型有好几 GB，时间取决于网络。
3. 如果出现 **Join Waitlist（加入候补）**：新版 Siri 是 Apple 服务端分批开放的，只能等待，与本地设置无关。

下载过程中再打开 Siri AI App，可能仍提示资源未就绪，属正常。

## 5.5 第一次真实使用

资源就绪后：

1. 打开 **Siri AI**（`/System/Applications/Siri AI.app`），点 **新对话**。
2. 先问一个**不需要联网**的问题测试本地/云端生成，例如：
   *Write two sentences about a purple paper boat on an imaginary moon.*
3. 再试写作工具（任意文本框里选中文字 → 右键 → Writing Tools）。

作者此时：生成、追问、写作工具、PCC 云端功能都可用；但**联网搜索类问题**（天气、新闻、"Apple 的 CEO 是谁"）报错 *Something's wrong*。这是网络层的问题，见第 6 步。

## 5.6 每次重启后都要再做一次

**重要发现**：普通重启（关机再开）后，资格又会回到 2。原因同 5.1：每次开机 eligibilityd 都比 RegionSpoof 早。

- 手动解决：每次开机登录后运行一次 `sudo launchctl reboot userspace`。
- 自动解决：见 [第 7 步](07-重启后自动恢复.md)。

注意：用户空间重启**不会**重新触发这个问题（内核没重启，扩展一直在），所以只需要在每次"真正的重启"之后做一次。
