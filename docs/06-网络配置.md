# 第 6 步：网络配置——PCC、Siri 联网搜索、ChatGPT 扩展

> 目标：解决"Siri 能聊天，但一问天气/新闻就报错""ChatGPT 扩展登录最后一步失败"这类问题。
> 这是作者花时间最多、也是上游项目没有覆盖的部分。

本文以 **Surge for Mac** 为例（作者使用的工具）。其他支持"规则分流 + 虚拟网卡（TUN）"的工具原理相同，配置写法不同。本文不提供、也不推荐任何代理服务。

---

## 6.1 先搞清楚：不同功能走的是不同的进程和域名

| 功能 | 主要进程 | 主要域名（示例） | 需要的出口 |
|---|---|---|---|
| 新版 Siri 对话 | `assistantd` 等 | `guzzoni.apple.com`、`*.smoot.apple.com` | 美国（与账户/资格一致的支持地区） |
| PCC 私有云计算 | `privatecloudcomputed` 等 | `mask*.icloud.com`、`*.apple-relay.*`、`gateway.icloud.com` | 稳定的支持地区 |
| **Siri 联网搜索**（天气、新闻、知识问答） | **`searchtoold`** | **`api-siri-prod.apple.com`** | 美国 |
| 天气卡片 | — | `weatherkit.apple.com` | 美国 |
| ChatGPT 扩展 | 系统组件 + 浏览器 | `*.openai.com`、`chatgpt.com` 等 | OpenAI 支持的地区 |

把 Apple Intelligence 相关域名**统一分到一个固定的美国出口**，比"全部走代理"或"全局模式"更稳。完整规则见 [`examples/surge-apple-intelligence.conf`](../examples/surge-apple-intelligence.conf)。

> 注意：很多公共规则集会把 Apple 的整个 `17.0.0.0/8` 网段设为"国内直连"。这对普通 Apple 服务没问题，但会坑 Siri 联网搜索，原因见 6.3。

---

## 6.2 症状

- Siri AI 能生成、能追问、写作工具正常；
- 但一问需要联网搜索的问题（"Who is the CEO of Apple"、"今天纽约天气怎么样"、"旧金山今天的头条新闻"）就显示：
  *Sorry, something's gone wrong* / *Uh oh, something's wrong* / *We've had a problem*。
- 同一个账户的 iPhone 上一切正常。

---

## 6.3 根因（三层叠加）

### 第一层：搜索服务的沙盒只允许连 443 端口

macOS 27 中负责联网搜索的是 `searchtoold`。它的沙盒配置文件：

```
/System/Library/Sandbox/Profiles/com.apple.omniSearch.searchtoold.sb
```

里面默认拒绝一切网络，**只放行连接远端 443 端口**：

```scheme
(allow network-outbound
    (remote ip "*:443"))
```

而 Surge 的"系统代理"让所有程序先连本机 `127.0.0.1:6152`（HTTP）/ `6153`（SOCKS）。端口不是 443 → **在本机就被沙盒拒绝**（EPERM，Operation not permitted），请求根本到不了 Surge。

对照：负责 Siri 对话的 `assistantd`，沙盒允许任意端口，所以它能走系统代理——这就是"能聊天、不能搜索"的原因。iPhone 上 Surge 本来就以 VPN 隧道方式工作，没有这个问题。

用日志可以直接看到（在 Siri 里提问的同时运行）：

```bash
log stream --level debug --style compact --predicate 'process == "searchtoold"' \
  | grep -E 'connectx|Operation not permitted|6152|6153'
```

### 第二层：绕过代理后，请求只剩 IP，被分流规则送去了国内直连

开启 Surge **增强模式**（虚拟网卡）后，`searchtoold` 直接连 443，能进入 Surge 了。但如果系统 DNS 不是 Surge 负责（例如开着 Tailscale 的 MagicDNS，见 6.5），程序拿到的是**真实 IP**，Surge 只看到 `17.x.x.x:443`：

```
17.248.x.x:443 (api-siri-prod.apple.com)
  → 规则命中 Apple.list 里的 IP-CIDR 17.0.0.0/8 → 国内直连
  → TCP 连上了，但 Apple 服务器 0 字节直接断开（Closed by remote）
```

Apple 服务端会拒绝来自中国大陆直连的该类请求。

### 第三层：DNS 污染

如果系统 DNS 最终转给了国内 DNS（例如 Tailscale MagicDNS 的上游是运营商 DNS），所有"自己解析域名、不走代理"的程序会拿到**被污染的地址**，例如：

```
chatgpt.com                      → 一个 Facebook 网段的地址（典型污染）
codex-cloud-backend.chatgpt.com  → 一个连上就被拒绝的地址
```

这会导致 ChatGPT 扩展登录最后一步失败、某些 App 的后台连接失败。

## 6.4 解法（作者最终方案，已验收）

| 设置 | 值 | 作用 |
|---|---|---|
| Surge 系统代理 | **开** | 其他 App 照常走代理 |
| Surge 增强模式 | **开** | 接住不走代理的流量（包括 searchtoold） |
| `skip-proxy` 增加 | `api-siri-prod.apple.com` | 让 searchtoold 不去连本机代理端口，改由增强模式接管 |
| 规则（放在 Apple.list 等规则之前） | `PROCESS-NAME,searchtoold,<你的美国策略组>` | 不管 DNS 返回什么，搜索服务的流量都走美国 |
| Apple Intelligence 域名规则 | 见示例文件 | 统一走美国出口 |

Surge 配置片段（`[General]` 中的 skip-proxy 是在你原有列表后面**追加**）：

```ini
[General]
skip-proxy = <原有内容>, api-siri-prod.apple.com

[Proxy Group]
🧠 Apple Intelligence = select, <你的美国节点1>, <你的美国节点2>

[Rule]
PROCESS-NAME,searchtoold,"🧠 Apple Intelligence"
DOMAIN-KEYWORD,siri,"🧠 Apple Intelligence"
# ……其余 Apple Intelligence 域名规则见 examples/
```

### 第一次开增强模式

需要安装 Surge 的网络扩展和 VPN 配置：Surge 会弹窗，点 **Install** 后到 **系统设置 → 通用 → 登录项与扩展 → 网络扩展** 打开 Surge，再点 **Set up** 允许添加 VPN 配置。命令行 `surge-cli feature set enhanced-mode on` 在未安装扩展时只会报 *Failed*。

### 为什么不"关系统代理、只开增强模式"

上游项目建议 Surge 用户"只开增强模式、不开系统代理"。没有其他 VPN 时这确实可行（作者的对照实验中，这样搜索也成功了）。但如果你同时用 Tailscale 等 VPN，见下面的坑，**保留系统代理 + 上表的定向修复**更稳。

### ⚠️ 重要：不要把 skip-proxy 这条加进 iPhone 用的配置

iPhone 没有进程规则（`PROCESS-NAME` 在 iOS 上被忽略），iPhone 上的 searchtoold 走代理本来就正常。加了 skip-proxy 反而会让它以 IP 形式进入隧道、掉进 17.0.0.0/8 直连，**把 iPhone 的 Siri 搜索弄坏**。Mac 和 iPhone 共用配置的，请给 Mac 单独做一个配置。

## 6.5 同时使用 Tailscale 的人必看

### 坑 1：Tailscale MagicDNS 导致 DNS 污染

开着 Tailscale 的 **Use Tailscale DNS**（MagicDNS）时，系统首选 DNS 是 `100.100.100.100`，普通域名被转给国内 DNS → 污染（6.3 第三层），并且 Surge 拿不到域名。

解法：让系统 DNS 交给 Surge，Tailscale 设备名单独交给 MagicDNS：

```bash
# 关掉 Tailscale 接管系统 DNS（Tailscale 连接照常）
/Applications/Tailscale.app/Contents/MacOS/Tailscale set --accept-dns=false
# 想恢复：--accept-dns=true
```

```ini
[General]
always-real-ip = *.ts.net, <设备短名1>, <设备短名2>

[Host]
*.ts.net = server:100.100.100.100
<设备短名1> = server:100.100.100.100
<设备短名2> = server:100.100.100.100
```

验证：

```bash
scutil --dns | grep -m1 nameserver               # 首选应为 198.18.0.2（Surge）
dscacheutil -q host -a name <设备>.<你的tailnet>.ts.net   # 应为 100.x 地址
dscacheutil -q host -a name chatgpt.com          # 不应再是 Facebook 网段
```

以后新增 Tailscale 设备：完整名字（`xxx.<tailnet>.ts.net`）自动可用；短名字需要在配置里补一行。

### 坑 2：Tailscale 连着时，不要关 Surge 的系统代理

作者的 Tailscale VPN 服务配置里残留了一份指向 `127.0.0.1:6152` 的代理设置（不归 Surge 管）。此时执行"关闭系统代理"，Surge 会删掉 Wi‑Fi 等所有网络服务上的代理，却因为系统全局代理仍然存在而报 *Failed*，并且**认为自己仍是开启状态、不再写回**。网络表面正常，实际上只靠 Tailscale 那份残留在撑，一旦 Tailscale 断开就没有代理了。**作者踩了两次。**

恢复：退出并重新打开 Surge（启动日志会出现 `Set proxy settings for N services`）。

检查是否有残留：

```bash
scutil <<< 'list .*Proxies'      # 如果 Tailscale 的服务 ID 下有 VPN/Proxies，就是残留
```

### 坑 3：`scutil --nc stop Tailscale` 断不开

Tailscale 开着"按需连接"时，命令断开后会立刻自动重连。需要真正断开时，在 Tailscale App 里断开。

## 6.6 ChatGPT 扩展登录

路径：**系统设置 → Siri → ChatGPT Extension → Sign In…**

作者的现象：浏览器里的 OpenAI 登录和验证全部通过、也收到了"新登录"邮件，但最后一步弹出 *Unable to Sign In*。

原因：浏览器走代理没问题，但最后一步由系统组件完成，它自己解析域名——拿到了被污染的地址（6.3 第三层）。按 6.5 关掉 Tailscale DNS 接管后，**重新登录一次就成功了**。

> 没有用 Tailscale 也遇到同样问题的，检查 `scutil --dns` 的首选 DNS 是不是国内 DNS，以及 OpenAI 相关域名有没有分到 OpenAI 支持地区的出口。

## 6.7 公司/路由器已有透明代理（如 OpenClash 软路由）

作者把机器带到公司（网关是 OpenWrt + OpenClash 软路由），在"Surge 系统代理 + 增强模式"叠加在路由器透明代理之上的情况下验收全部通过：外网、Claude、ChatGPT、Codex、Tailscale、Siri 联网搜索均正常，Surge 请求 0 失败。Surge 的直连流量会显式绑定物理网卡出去，不会和路由器的 `198.18.x` 假地址打环。

不同公司网络差异很大，**请自己验收**，不要直接假设没问题。

## 6.8 验收清单

在 Siri 里问 *Who is the CEO of Apple* 和 *今天纽约天气怎么样*，同时：

```bash
# Surge 最近的请求：searchtoold 应走你的美国策略、收到数十 KB 数据
/Applications/Surge.app/Contents/Applications/surge-cli --raw dump recent | python3 -c '
import json,sys,os
d=json.load(sys.stdin); rs=d.get("requests",d) if isinstance(d,dict) else d
for r in rs:
    if os.path.basename(r.get("processPath","") or "")=="searchtoold":
        print(r.get("URL"), r.get("policyName"), r.get("rule"), "in=", r.get("inBytes"))'
```

作者验收时：`searchtoold → api-siri-prod.apple.com:443 → PROCESS-NAME → 美国节点`，收到 34–37 KB，Siri 正常回答新闻、天气和 CEO 问题。
