# 第 4 步：安装并批准内核扩展

> 目标：把 RegionSpoof 装进系统、获得批准、重启后自动加载，设备地区变成 LL/A。

## 4.1 安装前再检查一次

```bash
csrutil status | grep -i kext            # Kext Signing: disabled
ls /Library/Extensions/RegionSpoof.kext 2>/dev/null && echo "已存在，先查清楚再继续"
```

## 4.2 复制到系统目录

```bash
OUT=~/Library/Caches/RegionSpoof-build/out
sudo cp -R "$OUT/RegionSpoof.kext" /Library/Extensions/
sudo chown -R root:wheel /Library/Extensions/RegionSpoof.kext
sudo chmod -R go-w /Library/Extensions/RegionSpoof.kext

# 核对：和第 2 步记下的 SHA256 一致，签名仍然有效
shasum -a 256 /Library/Extensions/RegionSpoof.kext/Contents/MacOS/RegionSpoof
codesign --verify --strict --verbose=2 /Library/Extensions/RegionSpoof.kext
```

## 4.3 请求加载一次（第一次一定会被拒，这是正常的）

```bash
sudo kmutil load -p /Library/Extensions/RegionSpoof.kext
echo "exit=$?"
```

第一次会失败（作者看到退出码 27），提示扩展**尚未获得批准**。这一步的作用就是让系统登记这个扩展、出现批准按钮。

> 如果提示的是 *Your current security settings prevent the installation of system extensions*，说明第 3 步的"允许用户管理内核扩展"没开，回恢复模式补上。

## 4.4 在系统设置里批准

1. **系统设置 → 隐私与安全性**，往下滚到"安全性"。
2. 会看到类似 *System software from developer "Unidentified - RegionSpoof" was blocked from loading*，点 **允许（Allow）**，输入密码。
3. 系统提示需要重启，点 **重新启动**。

## 4.5 重启后验证

```bash
# 已加载
kmutil showloaded 2>/dev/null | grep RegionSpoof

# 地区已改：region-info 应显示 <4c4c2f41000…>（即 LL/A），country-of-origin 应显示 <"USA">
ioreg -rd1 -c IOPlatformExpertDevice | grep -E '"region-info"|"country-of-origin"'
```

作者重启后读到：`com.local.RegionSpoof` 已加载，`region-info` = `LL/A`（32 字节），`country-of-origin` = `USA`。

### 需要额外的开机加载脚本吗？不需要

上游项目会安装一个 LaunchDaemon 在开机时加载扩展、并强制重启 AI 服务。作者**没有安装它**：在 Apple 芯片上，已批准的内核扩展会被写入系统的辅助内核集合（AuxKC），**每次开机自动加载**，重启后已实测确认。

> AuxKC 实际位于 Preboot 卷（`kmutil inspect` 可查），而不是 `/Library` 下。**不要手动删除 Preboot 里的文件**。

## 4.6 此时 Siri AI 还是不能用——正常

作者在这一步之后发现：扩展已加载、地区已是 LL/A，但两项资格仍然是 `2`（不符合），Siri AI 仍提示不可用。原因和解法见下一步。
