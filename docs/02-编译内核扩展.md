# 第 2 步：从源码编译 RegionSpoof 内核扩展

> 目标：自己从源码编译出 `RegionSpoof.kext`，不使用任何来历不明的现成二进制。

## 2.1 它到底做了什么

RegionSpoof 来自开源项目 [SkyBlue997/enableMacosAI](https://github.com/SkyBlue997/enableMacosAI)。核心源码只有约 20 行，开机时在 `IOPlatformExpertDevice` 上写两个属性：

| 属性 | 原值（国行） | 改后 |
|---|---|---|
| `region-info` | `CH/A` | `LL/A`（美版） |
| `country-of-origin` | `CHN` | `USA` |

系统里所有进程通过 MobileGestalt 读到的"设备地区"就变成了美版，资格判断里的"设备地区"这一项就能通过。

它**不会**改你的账户、定位、网络，也不涉及新版 Siri 的候补名单、PCC 或 ChatGPT 扩展。那些是另外的关卡。

> 小提醒：源码里的 `stop()` 不会把属性改回去。卸载后要**重启**才会恢复成 CH/A（见第 9 步）。

## 2.2 为什么要自己编译，而不是直接用仓库里的成品

作者审阅上游提交 `9c617ed` 时发现：
- 仓库自带的 `RegionSpoof.kext` 二进制里的日志字符串与当前源码**不一致**，无法证明它是由这份源码编译而来（不代表它有恶意，只是无法核对）。
- 上游的一键 `install.sh` 会做很多额外的事：改写 boot-args、覆盖旧文件、强制重启多个 AI 系统服务、加载失败也提示成功等。作者选择**不运行它**，改为下面的手动受控步骤。

## 2.3 获取源码（固定到具体提交）

**不要放在 iCloud 同步的目录**（如"文稿"/"桌面"开启了 iCloud 同步时）。作者踩过坑：放在同步目录里，文件会被加上 `com.apple.FinderInfo` / fileprovider 扩展属性，导致后面严格签名验证失败。建议放在用户缓存目录：

```bash
mkdir -p ~/Library/Caches/RegionSpoof-build && cd ~/Library/Caches/RegionSpoof-build
git clone https://github.com/SkyBlue997/enableMacosAI.git
cd enableMacosAI
git checkout 9c617ed94974173c6250819e5a08f95f5328d7d8   # 本文验证过的版本
```

先**读一遍** `src/RegionSpoof.cpp`、`src/kmod_info.c`、`src/Info.plist` 三个文件，确认只做了上面说的事。如果你使用更新的提交，请自己审阅改动。

## 2.4 编译（普通用户即可，不需要 sudo）

```bash
cd ~/Library/Caches/RegionSpoof-build/enableMacosAI
OUT=~/Library/Caches/RegionSpoof-build/out
mkdir -p "$OUT"

SDK="$(xcrun --show-sdk-path)"
KH="$SDK/System/Library/Frameworks/Kernel.framework/Headers"

# 1) 编译 kext 主体
xcrun clang++ -arch arm64e -isysroot "$SDK" -I"$KH" \
  -DKERNEL -DKERNEL_PRIVATE -DDRIVER_PRIVATE -DAPPLE -DNeXT \
  -fno-builtin -fno-common -fapple-kext -mkernel \
  -std=c++17 -fno-rtti -fno-exceptions -fno-stack-protector -O2 \
  -c src/RegionSpoof.cpp -o "$OUT/RegionSpoof.o"

# 2) 编译 kmod 入口（提供链接必需的 _kmod_info 符号）
xcrun clang -arch arm64e -isysroot "$SDK" -I"$KH" \
  -DKERNEL -DKERNEL_PRIVATE -DAPPLE \
  -fno-builtin -fno-common -fapple-kext -mkernel -O2 \
  -c src/kmod_info.c -o "$OUT/kmod_info.o"

# 3) 链接
xcrun clang++ -arch arm64e -isysroot "$SDK" -nostdlib -fapple-kext \
  -Xlinker -kext -lkmod -lkmodc++ -lcc_kext \
  -o "$OUT/RegionSpoof" "$OUT/RegionSpoof.o" "$OUT/kmod_info.o"

# 4) 组装 bundle 并 ad-hoc 签名
rm -rf "$OUT/RegionSpoof.kext"
mkdir -p "$OUT/RegionSpoof.kext/Contents/MacOS"
cp src/Info.plist "$OUT/RegionSpoof.kext/Contents/Info.plist"
cp "$OUT/RegionSpoof" "$OUT/RegionSpoof.kext/Contents/MacOS/RegionSpoof"
codesign -f -s - "$OUT/RegionSpoof.kext"
```

编译 `kmod_info.c` 时出现 `-fapple-kext` 对 C 无效之类的警告是正常的。

> 与上游 BUILD.md 的区别：输出放在自己的私有目录（不用固定的 `/tmp`）、编译和签名不用 `sudo`、不删除仓库自带文件。`chown root` 留到安装时再做。

## 2.5 验证产物

```bash
cd ~/Library/Caches/RegionSpoof-build/out
file RegionSpoof.kext/Contents/MacOS/RegionSpoof          # 应为 Mach-O 64-bit kext bundle arm64e
codesign --verify --strict --verbose=2 RegionSpoof.kext   # 应通过
codesign -dv RegionSpoof.kext 2>&1 | grep -E 'Identifier|Signature'   # Identifier=com.local.RegionSpoof, Signature=adhoc
plutil -lint RegionSpoof.kext/Contents/Info.plist
strings RegionSpoof.kext/Contents/MacOS/RegionSpoof | grep RegionSpoof:   # 日志字符串应与源码一致
shasum -a 256 RegionSpoof.kext/Contents/MacOS/RegionSpoof  # 记下来，安装后再比对
```

作者环境：Xcode 27.0（27A266a）、Apple clang 21.0.0、macOS 27.0 SDK，全部步骤一次通过。

> 编译成功只代表"产物生成了"，不代表能加载、更不代表 Siri 能用。

## 2.6 系统大版本更新后

内核扩展与系统版本相关。macOS 升级后如果加载失败，用同样的命令重新编译即可。
