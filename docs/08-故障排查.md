# 第 8 步：故障排查——症状 → 原因 → 解法

先运行只读体检，看清楚卡在哪一关：

```bash
sudo bash scripts/check-status.sh
```

## 资格关

| 症状 | 最可能的原因 | 解法 |
|---|---|---|
| `kmutil load` 提示 *security settings prevent the installation of system extensions* | 启动安全策略没开"允许用户管理内核扩展" | 回恢复模式补开（第 3.3 节），再执行一次 `csrutil enable --without kext` |
| `kmutil load` 退出码 27 / not approved | 还没批准 | 系统设置 → 隐私与安全性 → 允许 → 重启（第 4.4 节） |
| *Bad code signature* / 签名失败 | Kext Signing 没关；或在 iCloud 同步目录编译导致扩展属性污染 | `csrutil status` 确认 Kext Signing: disabled；在 `~/Library/Caches` 下重新编译 |
| 扩展已加载、地区是 LL/A，但资格仍是 2 | eligibilityd 开机时已缓存旧地区 | `sudo launchctl reboot userspace`（第 5 步） |
| `launchctl kickstart -k system/com.apple.eligibilityd` 报 150 | SIP 仍保护系统服务（正常） | 不要去完全关 SIP，用用户空间重启 |
| 用户空间重启后资格仍是 2 | 账户地区是中国大陆；语言不一致或非英文 | 查第 1.3、1.4 节；看 `PlistBuddy ... :status` 里各输入 |
| 每次关机再开机后 Siri AI 又不可用 | 同上：每次开机 eligibilityd 都比扩展早 | 手动用户空间重启，或装第 7 步的自动任务 |
| 系统设置出现 Join Waitlist | 新版 Siri 服务端分批开放 | 只能等待 |

## 网络关

| 症状 | 最可能的原因 | 解法 |
|---|---|---|
| 能对话、写作工具正常，但天气/新闻/知识问答报 *Something's wrong* | `searchtoold` 沙盒只准 443，连不上本机代理端口 | 第 6.4 节：增强模式 + skip-proxy + 进程规则 |
| 开了增强模式，搜索仍失败；Surge 里 searchtoold 的请求是 `17.x.x.x:443`、走 DIRECT、0 字节 | 只剩 IP，被 `17.0.0.0/8 → DIRECT` 规则送回国内，Apple 直接断开 | 加 `PROCESS-NAME,searchtoold,<美国组>` 并放在 Apple 规则集之前 |
| `chatgpt.com` 等解析到奇怪地址（如 Facebook 网段） | DNS 污染（常见于 Tailscale MagicDNS 转发国内 DNS） | 第 6.5 节：`tailscale set --accept-dns=false` + Surge `[Host]` |
| ChatGPT 扩展：网页登录都通过、收到邮件，最后一步 *Unable to Sign In* | 系统组件自己解析域名，被污染 | 修好 DNS 后重新登录（第 6.6 节） |
| 关 Surge 系统代理报 *Failed*，之后 Wi‑Fi 代理设置消失 | Tailscale VPN 服务里残留一份代理设置 | 退出并重新打开 Surge；Tailscale 连着时不要关系统代理（第 6.5 节坑 2） |
| 开增强模式报 *Failed to enable* | Surge 网络扩展/VPN 配置未安装 | 在 Surge 界面里点 Install、Set up，并在系统设置批准 |
| PCC 云端功能时好时坏 | 中继/证明节点、限流、节点不稳 | 不要连续重试；上游项目提供 PCC 只读诊断器 |

## 排查工具

```bash
# 实时看搜索服务的网络错误（在 Siri 提问时运行）
log stream --level debug --style compact --predicate 'process == "searchtoold"' \
  | grep -E 'connectx|Operation not permitted|RPCError'

# 看某个沙盒允许哪些网络连接
grep -n -A2 'network-outbound' /System/Library/Sandbox/Profiles/com.apple.omniSearch.searchtoold.sb

# 看系统 DNS 与代理
scutil --dns | head -20
scutil --proxy

# Surge：某个域名会命中哪条规则（只能模拟域名，模拟不了"只有 IP"的请求）
/Applications/Surge.app/Contents/Applications/surge-cli rule match api-siri-prod.apple.com
```

> 经验：Siri 界面上的 *Server rejected RPC* 等文字**不代表地区被拒**。作者遇到的这类报错，真实原因是请求在本机就被拦截了。一定要看实际连接日志，再下结论。

> 作者机器上 `log show`（查历史日志）读不出持久日志，只能用 `log stream` 实时抓。如果你也遇到，换用 `log stream` 并在问题发生时同步采集。
