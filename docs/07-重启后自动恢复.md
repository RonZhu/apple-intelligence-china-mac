# 第 7 步：重启后自动恢复资格（可选，实验性）

> 目标：每次普通重启后，不用手动输入 `sudo launchctl reboot userspace`。

> ⚠️ **实验性**：这个开机任务已通过逻辑测试（7 种情况的模拟运行），但截至 2026-10-12 **尚未在作者机器上经过真实重启验证**。不想冒险的话，继续每次开机后手动执行一次即可（第 5.6 节）。

## 7.1 它做什么

一个开机时以 root 运行的 LaunchDaemon（`com.local.ai-eligibility-fix`），逻辑：

1. 等 RegionSpoof 加载、确认地区已是 LL/A（最多等 5 分钟；没加载就什么都不做）。
2. 再等 20 秒，让 eligibilityd 有机会写出资格。
3. 如果当前 eligibilityd 已经判两项都是 4 → 什么都不做。
4. 否则，在**内核开机 15 分钟内**、并且**本次开机还没做过**的前提下，执行一次 `launchctl reboot userspace`。
5. 用户空间重启后脚本会再次运行，看到"本次开机已做过"的标记，只复查并记录结果，**绝不会循环重启**。

安全设计：
- 每次内核开机（以 `kern.bootsessionuuid` 区分）最多触发一次，用原子的 `mkdir` 做标记。
- 开机超过 15 分钟不动作，避免在你用电脑时突然退出所有 App。
- 应急开关：`sudo touch /var/db/com.local.ai-eligibility-fix/disabled` 后不再做任何事。
- 日志：`/var/log/com.local.ai-eligibility-fix.log`。

实际体验：开机 → 登录界面出现 → 约半分钟后屏幕黑一下（用户空间重启）→ 再次出现登录界面 → 登录即可，此时资格已恢复。如果你开机后很快登录并打开了 App，这些 App 会被退出一次。

## 7.2 安装

**请在开机 15 分钟以后安装**（安装脚本会检查），否则安装时可能立即触发一次用户空间重启。

```bash
cd scripts/auto-eligibility-fix
sudo bash install.sh
```

先想看看它会怎么判断、但不真正重启，可以用测试模式（需 root 才能读资格文件）：

```bash
sudo DRYRUN=1 MAX_UPTIME=999999 SETTLE=0 \
  STATE_DIR=/tmp/aefix-test bash com.local.ai-eligibility-fix.sh
```

## 7.3 下次重启后检查

```bash
cat /var/log/com.local.ai-eligibility-fix.log
bash scripts/check-status.sh
```

正常的日志顺序：`start …` → `com.local.RegionSpoof loaded` → `running launchctl reboot userspace` → （重启后）`start …` → `post-fix check: GREYMATTER=4 APP_INTENTS=4 fresh_eligible=yes`。

## 7.4 卸载

```bash
cd scripts/auto-eligibility-fix
sudo bash uninstall.sh
```
